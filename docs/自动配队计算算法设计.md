# 自动配队算法设计

术语以 [`CONTEXT.md`](../CONTEXT.md) 为准。需求原文：[`自动配队计算算法需求.md`](./自动配队计算算法需求.md)。问题归类与文献对照：[`research/auto-team-algorithm-survey.md`](./research/auto-team-algorithm-survey.md)。

配队是独立于查看器的入口，不复用查看器里 `id < 0` 的三个职阶占位。

**复核修订版：保留精确算法。** 礼装是全队光环、羁绊15 光环人数由锁定格固定之后，从者分数在「光环配置已定」时线性可加。本文更新锁定可行性、礼装枚举与选人内核；历史实现 `edb160d` 的反例和性能记录见两份复核报告。

原始需求允许用近似换取性能；「只做精确算法、两秒目标、使用 Worker」属于设计 v1 的技术选择。本轮实现精确求解器修复与加速，不包含 Worker/UI、CP-SAT、近似算法或分支定界；两秒不是复杂度推导能保证的承诺。修订实现已完成72组桌面实测，部分满库存全冠位配置仍未达标，详见[验证与性能记录](./research/auto-team-algorithm-review-2026-09-07.md#94-实施后验证与性能)。

| 礼装库存             | 哪些特性/职阶/10% 可用          | 每种 0 或 1 张；5% 无限；15% 仅助战、至多 1 张 |
| 职阶虚拟配额         | `quotaClass[职阶][星级]`        | 默认每档 6                                     |
| 通用虚拟配额         | `quotaGeneric[星级]`            | 默认每档 6                                     |

助战格不选从者、不消耗 cost、该格从者不计入羁绊收益；只规划礼装。助战礼装不占本队库存，可与本队重复。

上表为产品输入范围。同步求解内核还接受1～6个位置、0～118的整数cost，便于求解小实例和独立穷举验证；页面接入时按产品范围约束输入，不把内核接受更小实例视为产品范围变更。

`init` 的资源包含完整特性礼装目录 `traitCeTypes`，由 `data.typeList.map((_, id) => id)` 提供；与完整职阶礼装目录 `classCeClasses` 一样，不从当前图鉴的命中特性或本队库存推导。本队库存和锁定礼装必须属于目录，即使没有从者命中，助战也可锁定目录中的特性礼装。

冠位：第一张礼装不计 cost，第二张计 16。非冠位本队格的那一张礼装计 16。助战礼装一律不计 cost。

从者 cost：★5=16、★4=12、★3=7、★2/★0=4、★1=3；玛修（`data.json` id=1）=0。

## 2. 配队池

### 2.1 真从者

- 来源：`data.json` 的 `servantList`（约 436 人），**不含**查看器虚拟从者。
- 过滤：隐藏、星级、职阶，语义与 `src/stores/servant.ts` 一致。
- `typeComments`（灵衣等）仍视为具备该特性。
- 锁定从者即使被过滤掉也必须上场。

### 2.2 当前职阶范围

- 职阶筛选非空：范围 = 选中职阶。
- 职阶筛选为空：范围 = `classList` 全部 15 个职阶。

有职阶礼装的职阶（本项目写死）：`Caster`、`Rider`、`Saber`、`Assassin`（`classBonusList`）。其余职阶没有职阶礼装。

### 2.3 职阶虚拟从者

对每个职阶 \(C\in\{\mathrm{Caster},\mathrm{Rider},\mathrm{Saber},\mathrm{Assassin}\}\)、星级 \(r\in\{1,2,3,4,5\}\) 生成一类占位，当且仅当：

1. 库存含 \(C\) 的职阶礼装；
2. \(C\) 在当前职阶范围内；
3. \(r\) 通过星级筛选（未筛星级则全部通过）；
4. `quotaClass[C][r] > 0`。

该类可上场个数 ≤ 配额。无特性，职阶为 \(C\)，cost 按星级表。可获羁绊，不发光环。结果里用独立 id 区分（不要用查看器的 -99 段）。语义：任意一名该职阶、该星级的从者。

### 2.4 通用虚拟从者

对星级 \(r\in\{1,2,3,4,5\}\) 生成一类占位，当且仅当：

1. 当前职阶范围里**存在没有职阶礼装的职阶**；
2. \(r\) 通过星级筛选；
3. `quotaGeneric[r] > 0`。

无职阶、无特性，只吃基础 100% 与通用礼装。代表「职阶虚拟从者以外、又没有职阶礼装可吃」的从者。

对照：

| 职阶筛选                      | 库存（示意）           | 职阶虚拟     | 通用虚拟                                |
| ----------------------------- | ---------------------- | ------------ | --------------------------------------- |
| 无                            | 四职阶礼装都有，配额足 | C/R/S/A 都进 | 进（范围含 Archer 等）                  |
| 仅 Rider                      | 有 Rider 礼装          | Rider 进     | **不进**                                |
| Rider + Archer                | 有 Rider 礼装          | Rider 进     | **进**（Archer 无职阶礼装）             |
| 仅 Archer                     | —                      | 不进         | **进**                                  |
| 仅 Caster                     | 无 Caster 礼装         | 不进         | **不进**（Caster 属于有职阶礼装的职阶） |
| Caster+Rider+Saber+Assassin   | 四张都有               | 四职阶都进   | **不进**                                |

默认每星级配额 6 与「无限」在 \(K_{\max}\le 6\) 时等价；实现用 6，背包有上界。

## 3. 羁绊收益

只对**本队格**从者计收益。助战不计。

对从者 \(i\)：

- 不可获羁绊（锁定为羁绊15 且未开 16）：\(\mathrm{yield}_i=0\)，但仍占格、仍按是否羁绊15 计入 \(A\)。
- 可获羁绊：

\[
\mathrm{yield}_i = 100\% + \text{礼装光环}_i + 25\%\times A
\]

\(A\) = 锁定格中「羁绊15」从者人数，是输入常量。多道光环线性叠加，无上限。

**礼装光环**（谁戴无关，按场上佩戴张数叠；助战与本队各戴一张同类则叠两层）：

| 礼装               | 谁吃                                           |
| ------------------ | ---------------------------------------------- |
| 特性礼装 +20% / 张 | `types` 含对应特性的可获羁绊从者               |
| 职阶礼装 +20% / 张 | `class` 相同的可获羁绊从者（含该职阶虚拟从者） |
| 10% / 5% / 15%     | 所有可获羁绊从者                               |

15% 仅助战格可戴，库存视为 1 张。5% 张数不限。

令 \(G\) 为本队可获羁绊人数，\(\mathrm{copies}(c)\) 为礼装 \(c\) 的佩戴张数，\(m_c\) 为吃到 \(c\) 的可获羁绊人数（通用礼装 \(m_c=G\)）：

\[
\text{总收益} = G\cdot(1 + 0.25A) + \sum_c \mathrm{rate}(c)\cdot \mathrm{copies}(c)\cdot m_c
\]

**光环配置一旦固定，每个从者的分数只依赖自身特性/职阶/是否可获羁绊，从者之间不再耦合。**

## 4. 目标（字典序）

比较键一律从左到右，只输出一组最优。

**星级优先关闭（默认）**

1. 总羁绊收益最大；
2. 同收益则已用 cost（从者 + 礼装）最大。

**星级优先开启**

1. 在满足全部锁定约束的可行队伍中，本队格星级向量 \((n_5,n_4,n_3,n_2,n_1,n_0)\) 字典序最大。先扣锁定从者和锁定付费礼装的 cost，并确保只锁礼装的本队格也有从者；计算向量时**不预留可选付费礼装**。可选礼装不能降低该向量。
2. 同向量则总羁绊收益最大（选哪些高星、剩余 cost 带哪些礼装）。同星级里特性更匹配的真从者会自然压过虚拟从者。
3. 再取已用 cost 最大。

玛修按 ★4、cost 0 参与星级向量。助战格不进入星级向量。

**免费礼装**（助战全部、已占冠位本队格第一张）两种模式都必须填满，即使可获羁绊人数 \(G=0\)。未占本队格不能佩戴礼装。付费礼装在不损害前序目标的前提下按最高已用 cost 填充，\(G=0\) 时也适用。

锁定是硬约束。`lockedCes` 按礼装位置保存，元素允许 `null`，表示该位置没有锁定礼装、仍可自动填充；例如冠位 `[null, ce]` 只锁第二张。冲突、非法来源、有限库存超额或不存在满足全部锁定的可行队伍时抛出 `Error`，不得返回超预算或遗漏锁定的候选。空池且无锁定可以返回本队为空的合法结果；存在助战时仍填满其礼装。

## 5. 礼装打包

佩戴前提：该格有从者。助战格视为始终有从者（不指定是谁）。

占用哪些本队格（未锁定部分）：

- 有锁定从者或非空锁定礼装的本队格必须占用；只锁礼装时仍需从池中选人。
- 其余优先占冠位格，再占非冠位格。空置冠位格既少一个从者又少一个免费礼装位，严格劣于占用它（只要还放得下任何一个正收益从者）。
- 因此每个「上场人数 \(K\)」可取一个规范占用方案。枚举满足强制占位数的 \(K\) 到 \(K_{\max}\)；选人必须恰好满足该次人数。

得到占用方案后，列出礼装位：

- 免费位：助战 1 或 2 个 + 每个已占冠位本队格的第一张；
- 付费位：其余礼装位，每个 16 cost。

固定队伍打包：先保留锁定礼装及来源库存，按 `加成率 × 可获羁绊命中人数` 比较剩余候选。5% 是可重复候选，必须与特性/职阶/10% 一起比较，不能先装所有正收益特性礼装再补5%。本队在免费容量与预算允许的付费容量内取最高价值组合；助战从完整目录取最高价值合法组合，不受本队库存限制。有限种类在本队、助战各至多一张，5% 可重复。免费位全部填满；收益同为零时仍按最高 cost 填付费位。

锁定礼装：原位置固定，占用本来源的容量和有限份数；本队锁定占本队库存，助战无视本队库存。费用在枚举和选人之前预扣。打包不得接收负预算或用丢弃锁定修复不可行输入。

## 6. 主算法（精确）

朴素枚举从者×礼装约 \(10^{18}\)～\(10^{29}\)，不可用。见调研文档。

核心分解：

> 预处理锁定 → 枚举恰好人数与合法礼装配置 → 复用选择性光环分数 → 同 cost top-K、前缀和与人数向量枚举 → 恢复最终见证并复算。

### 6.1 光环配置

一个配置是各礼装的佩戴张数：

- 特性 8 种、职阶 3 种：各 0～2 张（本队 0～1 + 助战 0～1，受库存与助战格数约束）；
- 10%：0～2；
- 15%：0～1；
- 5%：0～礼装位总数。

只生成能按 §5 实际放置的配置。每个配置包含锁定前缀、来源张数、免费/付费容量、完整礼装 cost，以及可恢复到具体位置的放置见证。本队张数受库存限制；助战不占本队库存。只锁礼装的位置计入本次强制占位。

实现上不必生成 \(3^{11}\)：

1. 从本队库存扣除锁定有限礼装，枚举剩余特性/职阶/10% 子集；锁定位置不可覆盖；
2. 从完整14种目录枚举助战剩余位置的无序组合，有限种类不能在助战内重复，5% 可重复；锁定位置保留；
3. 枚举本队付费张数，以5%补足所选总张数和全部免费位，分别核对来源容量及预算。即使 \(G=0\) 也不能跳过必填免费位；
4. 只有合法性已成立，才能按相同光环、人数、礼装 cost 合并等价配置，保留任一合法见证。

无锁定的冠位助战由183个有序组合减为92个无序组合；去重不强制携带15%。实际合法配置数依赖人数、锁定与预算，必须实测，不能以宽松候选数冒充合法配置数。

### 6.2 从者线性分

配置 \(C\) 给定后，可获羁绊从者 \(i\) 的分数：

\[
v_i(C) = 1 + 0.25A + \sum_{c\in C} \mathrm{rate}(c)\cdot\mathrm{copies}(c)\cdot\mathbf{1}[i\text{ 吃到 }c]
\]

不可获羁绊：\(v_i=0\)。

### 6.3 默认模式：选人

对每个精确人数 \(K\) 和合法配置 \(C\)，扣除锁定从者及全部礼装 cost，在剩余池中恰好选 \(K'\) 人。人数不足或无预算内方案则跳过，由外层枚举更少人数。

1. 按实际 cost `{0,3,4,7,12,16}` 分组，在每组按该光环下收益保留前 \(K'\) 份。真从者仅一份，虚拟从者最多剩余配额份，并保留可恢复身份。
2. 为各组计算收益前缀和，枚举六组人数向量，要求人数和恰好为 \(K'\)、份数不超组容量、总 cost 不超剩余预算。
3. 比较 `(收益, 从者 cost)`，记录最优向量，最终按组前缀恢复名单；无需可变背包前驱。

精确性：同 cost 组最多选 \(K'\) 份。若用了排名更后的候选，总能用前 \(K'\) 中未选的一份替换，人数与 cost 不变、收益不降。固定组人数时前缀必然最优，枚举所有合法人数向量即可覆盖最优解。cost 0 只有玛修，\(K'=6\) 时最多336个恰好人数向量。

外层完整覆盖最优解的合法礼装配置 \(C^*\)；该配置下精确选出的同人数队伍不会比原最优队伍差，且仍有同一放置见证。因此可以直接比较全局目标。**取消每候选重新打包是基于合法、完整枚举的等价优化，不是旧规格本来要求的行为。** 最终恢复赢家的名单和礼装位置，重新计算收益与已用 cost，并核对所有硬约束。

### 6.4 星级优先：选人

**第一步：可行星级向量 \(n^\*\)。** 先扣锁定从者和锁定付费礼装 cost，计入锁定从者星级。对剩余池按 `(star,cost)` 统计合法份数，考虑玛修 cost 0 分支，枚举满足强制占位、人数和预算的向量，取 \((n_5,\ldots,n_0)\) 字典序最大者。不为可选礼装预留 cost，也不能只逐档贪心后忽略只锁礼装的位置缺人。若没有满足全部锁定的向量则抛出 `Error`。

**第二步：在恰好 \(n^\*\) 下最大化收益。** 对每个光环配置 \(C\)：

- 扣除锁定从者各档人数，按 `(star,cost)` 的收益前缀恰好选满剩余向量；★0 与 ★2 同 cost 但不能混档。
- ★4：玛修可用时分别构造「带玛修 + 其余四星最高分前缀」与「不带玛修 + 四星最高分前缀」。先过滤不可行分支，再按收益、总 cost 比较。
- 总从者 cost + 礼装 cost \(> W\) 则丢弃（**不许**为礼装少带一个高星）。
- 直接使用合法礼装放置见证更新最优，最终恢复和复算。

同星级同分数时，默认模式的第二关键字会选更贵的；星级优先在收益相同后再比总 cost，同样处理。职阶虚拟与通用虚拟同星、又都吃不到职阶礼装时分数相同：优先用通用虚拟从者，避免占职阶配额。

### 6.5 分数复用与实现边界

- 未锁定从者都可获羁绊。对于精确人数，基础收益、锁定羁绊15 光环和通用礼装都只增加公共常量：`G * (100 + 25*A + 5*ce5 + 10*ce10 + 15*ce15)`，其中 `ce5/ce10/ce15` 是对应通用礼装张数。选人排序只计算特性/职阶光环贡献。
- 相同特性/职阶张数向量可复用计分、top-K 与前缀和，查询不同人数、预算和通用礼装数量；不得跨不同选择性光环永久截断候选。
- 同桶保留足够的可选份数及可恢复 ID，不能只留最便宜/最贵两个代表。旧文的两个代表截断和「15%必带」均未在历史实现中实施，只是设计勘误。
- 真从者每人最多上场 1 次。虚拟从者按配额。
- 结果：每个本队格的从者（真 / 职阶虚拟 / 通用虚拟）、每个礼装位、总收益、已用 cost。多组最优只留一组。
- 本轮保持同步接口。Worker/UI、限时与取消另行接入；不增加求解器依赖或近似路径。

## 7. 复杂度

| 步骤                       | 规模与边界                                            |
| -------------------------- | ----------------------------------------------------- |
| 占用方案                   | 本队0～6人，按锁定强制占位过滤                        |
| 有限本队礼装               | 最多12种；实际枚举受锁定、容量与预算限制              |
| 未锁定冠位助战组合         | 92个无序组合                                          |
| 每种选择性光环计分及 top-K | 用最多6项小数组时约 \(O(PK)\)；复用后不随通用张数重复 |
| 默认精确人数向量           | 六种 cost，玛修最多一份，6人时至多336个               |
| 星级优先选人               | 固定星级向量，按星级/cost前缀和比较玛修分支           |
| 最终恢复                   | 仅恢复赢家，再按业务规则复算                          |

`P` 为剩余从者种类数，`K<=6`。上述是内核和组合规模，不是端到端耗时保证。全库存、冠位助战、不同锁定与模式必须分别测量，历史数据与实施后数据分开记录在复核报告中。

## 9. 例子

### 9.1 光环匹配

本队 2 Caster + 1 Saber，场上 1 张 Caster 礼装 + 1 张 5%：Caster 各 \(100+20+5=125\%\)，Saber \(105\%\)。助战再戴一张 Caster 礼装：Caster 各 \(145\%\)，Saber 仍 \(105\%\)。

### 9.2 默认 vs 星级优先

\(K_{\max}=5\)，\(W=80\)，无锁定，无冠位，无助战。池里有若干 ★1 多特性从者和 ★5。

- 默认：会带多张特性礼装（每张 16）和低星多特性从者，收益通常更高。
- 星级优先：先上 5 个 ★5（cost 80），付费礼装全空；再在这 5 个 ★5 里挑特性最能凑到**免费礼装**的组合。若无助战、无冠位，则没有任何免费礼装位，队伍就是 5 个收益 100% 的 ★5（再加锁定带来的 \(A\)）。

### 9.3 同收益刷 cost

星级优先关闭。某格用 ★4 或 ★5 收益同为 100%（都吃不到特性/职阶礼装），剩余 cost ≥ 16：换 ★5。玛修若与某 ★1 收益相同，默认模式会换成正 cost 的人；她通常特性更多，收益更高，不会走到这一步。

### 9.4 虚拟从者

只筛 Rider，有 Rider 礼装：只用 Rider 真从者 + Rider 虚拟从者。只筛 Rider+Archer：Rider 虚拟从者吃 Rider 礼装，Archer 空位用通用虚拟从者指代。
