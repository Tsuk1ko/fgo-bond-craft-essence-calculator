# 自动配队算法设计

术语以 [`CONTEXT.md`](../CONTEXT.md) 为准。需求原文：[`自动配队计算算法需求.md`](./自动配队计算算法需求.md)。问题归类与文献对照：[`research/auto-team-algorithm-survey.md`](./research/auto-team-algorithm-survey.md)。

配队是独立于查看器的入口，不复用查看器里 `id < 0` 的三个职阶占位。

**v1 结论：只实现精确算法。** 礼装是全队光环、羁绊15 光环人数由锁定格固定之后，从者分数在「光环配置已定」时线性可加，不必先做启发式。文档末尾仍列出局部最优 / 折中候选，供礼装种类变多时替换。

## 1. 输入

| 符号                 | 含义                            | 范围 / 默认                                    |
| -------------------- | ------------------------------- | ---------------------------------------------- |
| \(N\)                | 队伍位置（含助战格）            | 3～6                                           |
| \(S_{\mathrm{sup}}\) | 助战格数量                      | 0 或 1                                         |
| \(W\)                | cost 上限                       | 56～118                                        |
| 本队格               | \(K_{\max}=N-S_{\mathrm{sup}}\) | 2～6                                           |
| 冠位                 | 每个位置独立，含助战格          | 布尔                                           |
| 锁定                 | 任意格的从者和/或礼装           | 可空                                           |
| 羁绊15 / 开16        | 仅锁定从者可设                  | 默认否 / 否                                    |
| 星级优先             | 见 §4                           | 默认关                                         |
| 从者池过滤           | 隐藏、星级、职阶                | 与查看器同一套语义                             |
| 礼装库存             | 哪些特性/职阶/10% 可用          | 每种 0 或 1 张；5% 无限；15% 仅助战、至多 1 张 |
| 职阶虚拟配额         | `quotaClass[职阶][星级]`        | 默认每档 6                                     |
| 通用虚拟配额         | `quotaGeneric[星级]`            | 默认每档 6                                     |

助战格不选从者、不消耗 cost、该格从者不计入羁绊收益；只规划礼装。助战礼装不占本队库存，可与本队重复。

冠位：第一张礼装不计 cost，第二张计 16。非冠位本队格的那一张礼装计 16。助战礼装一律不计 cost。

从者 cost：★5=16、★4=12、★3=7、★2/★0=4、★1=3；玛修（`data.json` id=1）=0。

## 2. 配队池

### 2.1 真从者

- 来源：`data.json` 的 `servantList`（约 436 人），**不含**查看器虚拟从者。
- 过滤：隐藏、星级、职阶，语义与 `src/stores/servant.ts` 一致。
- `typeComments`（灵衣等）仍视为具备该特性。
- 锁定从者即使被过滤掉也必须上场。

### 2.2 当前职阶范围

- 职阶筛选非空：范围 = 选中职阶。
- 职阶筛选为空：范围 = `classList` 全部 15 个职阶。

有职阶礼装的职阶（本项目写死）：`Caster`、`Rider`、`Saber`（`classBonusList`）。其余职阶没有职阶礼装。

### 2.3 职阶虚拟从者

对每个职阶 \(C\in\{\mathrm{Caster},\mathrm{Rider},\mathrm{Saber}\}\)、星级 \(r\in\{1,2,3,4,5\}\) 生成一类占位，当且仅当：

1. 库存含 \(C\) 的职阶礼装；
2. \(C\) 在当前职阶范围内；
3. \(r\) 通过星级筛选（未筛星级则全部通过）；
4. `quotaClass[C][r] > 0`。

该类可上场个数 ≤ 配额。无特性，职阶为 \(C\)，cost 按星级表。可获羁绊，不发光环。结果里用独立 id 区分（不要用查看器的 -99 段）。语义：任意一名该职阶、该星级的从者。

### 2.4 通用虚拟从者

对星级 \(r\in\{1,2,3,4,5\}\) 生成一类占位，当且仅当：

1. 当前职阶范围里**存在没有职阶礼装的职阶**；
2. \(r\) 通过星级筛选；
3. `quotaGeneric[r] > 0`。

无职阶、无特性，只吃基础 100% 与通用礼装。代表「职阶虚拟从者以外、又没有职阶礼装可吃」的从者。

对照：

| 职阶筛选           | 库存（示意）           | 职阶虚拟   | 通用虚拟                                |
| ------------------ | ---------------------- | ---------- | --------------------------------------- |
| 无                 | 三职阶礼装都有，配额足 | C/R/S 都进 | 进（范围含 Archer 等）                  |
| 仅 Rider           | 有 Rider 礼装          | Rider 进   | **不进**                                |
| Rider + Archer     | 有 Rider 礼装          | Rider 进   | **进**（Archer 无职阶礼装）             |
| 仅 Archer          | —                      | 不进       | **进**                                  |
| 仅 Caster          | 无 Caster 礼装         | 不进       | **不进**（Caster 属于有职阶礼装的职阶） |
| Caster+Rider+Saber | 三张都有               | 三职阶都进 | **不进**                                |

默认每星级配额 6 与「无限」在 \(K_{\max}\le 6\) 时等价；实现用 6，背包有上界。

## 3. 羁绊收益

只对**本队格**从者计收益。助战不计。

对从者 \(i\)：

- 不可获羁绊（锁定为羁绊15 且未开 16）：\(\mathrm{yield}_i=0\)，但仍占格、仍按是否羁绊15 计入 \(A\)。
- 可获羁绊：

\[
\mathrm{yield}_i = 100\% + \text{礼装光环}_i + 25\%\times A
\]

\(A\) = 锁定格中「羁绊15」从者人数，是输入常量。多道光环线性叠加，无上限。

**礼装光环**（谁戴无关，按场上佩戴张数叠；助战与本队各戴一张同类则叠两层）：

| 礼装               | 谁吃                                           |
| ------------------ | ---------------------------------------------- |
| 特性礼装 +20% / 张 | `types` 含对应特性的可获羁绊从者               |
| 职阶礼装 +20% / 张 | `class` 相同的可获羁绊从者（含该职阶虚拟从者） |
| 10% / 5% / 15%     | 所有可获羁绊从者                               |

15% 仅助战格可戴，库存视为 1 张。5% 张数不限。

令 \(G\) 为本队可获羁绊人数，\(\mathrm{copies}(c)\) 为礼装 \(c\) 的佩戴张数，\(m_c\) 为吃到 \(c\) 的可获羁绊人数（通用礼装 \(m_c=G\)）：

\[
\text{总收益} = G\cdot(1 + 0.25A) + \sum_c \mathrm{rate}(c)\cdot \mathrm{copies}(c)\cdot m_c
\]

**光环配置一旦固定，每个从者的分数只依赖自身特性/职阶/是否可获羁绊，从者之间不再耦合。**

## 4. 目标（字典序）

比较键一律从左到右，只输出一组最优。

**星级优先关闭（默认）**

1. 总羁绊收益最大；
2. 同收益则已用 cost（从者 + 礼装）最大。

**星级优先开启**

1. 本队格星级向量 \((n_5,n_4,n_3,n_2,n_1,n_0)\) 字典序最大（先尽量多 ★5，再 ★4，…；能铺满就铺满）。计算该向量时**可以不带付费礼装**。不是随便塞 ★5：向量固定之后仍要最大化收益。
2. 同向量则总羁绊收益最大（选哪些高星、剩余 cost 带哪些礼装）。同星级里特性更匹配的真从者会自然压过虚拟从者。
3. 再取已用 cost 最大。

玛修按 ★4、cost 0 参与星级向量。助战格不进入星级向量。

**免费礼装**（助战全部、冠位第一张）两种模式都必须填满。空的只应是付费礼装格。

## 5. 礼装打包

佩戴前提：该格有从者。助战格视为始终有从者（不指定是谁）。

占用哪些本队格（未锁定部分）：

- 锁定格已占用。
- 其余优先占冠位格，再占非冠位格。空置冠位格既少一个从者又少一个免费礼装位，严格劣于占用它（只要还放得下任何一个正收益从者）。
- 因此每个「上场人数 \(K\)」对应唯一占用方案。枚举 \(K=K_{\mathrm{lock}},\ldots,K_{\max}\) 即可。

得到占用方案后，列出礼装位：

- 免费位：助战 1 或 2 个 + 每个已占冠位本队格的第一张；
- 付费位：其余礼装位，每个 16 cost。

打包规则：价值高的光环优先放进免费位，再放付费位；付费位在剩余 cost 不够时留空。5% 填剩余空位（免费位也填）。

锁定礼装：该位固定，占用库存（本队）或无视库存（助战）。

## 6. 主算法（精确）

朴素枚举从者×礼装约 \(10^{18}\)～\(10^{29}\)，不可用。见调研文档。

核心分解：

> 枚举光环配置 → 从者分数线性化 → 基数 + cost 背包（或按星级取 top）→ 用固定队伍再打包一次礼装作为最终方案。

### 6.1 光环配置

一个配置是各礼装的佩戴张数：

- 特性 8 种、职阶 3 种：各 0～2 张（本队 0～1 + 助战 0～1，受库存与助战格数约束）；
- 10%：0～2；
- 15%：0～1；
- 5%：0～礼装位总数。

只生成能按 §5 打包成功的配置。本队张数受库存限制；助战不占库存。

实现上不必生成 \(3^{11}\)：

1. 枚举本队使用的特性/职阶/10% 子集（仅库存里有的，\(2^{n_{\mathrm{owned}}}\)）；
2. 枚举助战 1～2 格的内容（约 \(13\) 或 \(13^2\)，再去掉 15% 重复）；
3. 剩余礼装位用 5% 填（受剩余 cost 约束时少填）。

典型库存 \(n_{\mathrm{owned}}\le 8\) 时，配置量在 \(10^3\)～\(10^4\) 量级。

### 6.2 从者线性分

配置 \(C\) 给定后，可获羁绊从者 \(i\) 的分数：

\[
v_i(C) = 1 + 0.25A + \sum_{c\in C} \mathrm{rate}(c)\cdot\mathrm{copies}(c)\cdot\mathbf{1}[i\text{ 吃到 }c]
\]

不可获羁绊：\(v_i=0\)。

### 6.3 默认模式：选人

对每个 \(K\)、每个合法 \(C\)：

- 预算 \(W' = W - \mathrm{CECost}(C)\)（免费礼装不减）。
- 锁定从者强制纳入，更新剩余人数 \(K'\) 与剩余预算。
- 在剩余池里选至多 \(K'\) 人，最大化 \(\sum v_i\)，其次最大化从者 cost；0-1 背包，状态 \((\text{人数},\text{cost})\)。

\[
O(|\mathrm{pool}|\cdot K\cdot W)\approx 436\cdot 6\cdot 118\approx 3\times 10^5
\]

虚拟从者按配额展开为至多 6 个相同物品（或分组背包：该类选 0～配额个）。

得到队伍后，用 §5 对**该队伍**再求一次最优打包（助战补 15% / 重复特性等）。以这次的 (收益, 总 cost) 更新全局最优。

正确性：最优队伍 \(T^*\) 的最优光环为 \(C^*\)。枚举扫到 \(C^*\) 时，背包在「假定戴 \(C^*\)」下选出的队伍不差于 \(T^*\)；再打包不会变差。故能取到全局最优。

### 6.4 星级优先：选人

**第一步：星级向量 \(n^*\)。** 只计从者 cost、忽略付费礼装。锁定从者的星级先计入。剩余格子与预算上，从 ★5 到 ★0 逐档：该档用**最便宜**的可用从者尽量多塞（★5 全是 16；★4 先玛修再 12；…），受池子与配额限制。得到 \(n^*=(n_5,\ldots,n_0)\)。

**第二步：在恰好 \(n^*\) 下最大化收益。** 对每个光环配置 \(C\)：

- 各星级内部 cost 均匀（★4 的玛修除外）：按 \(v_i(C)\) 取该档 top \(n_r\)。
- ★4：若 \(n_4\ge 1\) 且玛修可用，比较「带玛修 + top \(n_4-1\)」与「不带玛修 + top \(n_4\)」，先比收益再比能否塞进 \(W-\mathrm{CECost}(C)\)。
- 总从者 cost + 礼装 cost \(> W\) 则丢弃（**不许**为礼装少带一个高星）。
- 再打包、更新最优。

同星级同分数时，默认模式的第二关键字会选更贵的；星级优先在收益相同后再比总 cost，同样处理。职阶虚拟与通用虚拟同星、又都吃不到职阶礼装时分数相同：优先用通用虚拟从者，避免占职阶配额。

### 6.5 实现要点

- 放在 Web Worker 里跑，避免堵住 UI；预算 2s，典型库存应远小于此。
- 池子先按 `(star, class, typeBitset, canGain)` 分桶。同一配置下同桶分数相同，只保留「最便宜」与「最贵」两个 cost 变体即可覆盖「多塞人」与「同收益刷 cost」（玛修单独留）。
- 真从者每人最多上场 1 次。虚拟从者按配额。
- 结果：每个本队格的从者（真 / 职阶虚拟 / 通用虚拟）、每个礼装位、总收益、已用 cost。多组最优只留一组。

## 7. 复杂度

| 步骤             | 规模                                                 |
| ---------------- | ---------------------------------------------------- |
| 占用方案 \(K\)   | \(\le 6\)                                            |
| 光环配置（典型） | \(10^3\)～\(10^4\)                                   |
| 默认选人 DP      | \(3\times 10^5\) / 配置                              |
| 星级优先选人     | \(O(\|\mathrm{pool}\|\log\|\mathrm{pool}\|)\) / 配置 |
| 固定队伍打包     | \(O(\#\text{礼装种类})\)                             |

最坏（11 种礼装都有、助战冠位双格）配置数上升一个数量级：用「只枚举能打包的配置 + 分桶」压回 2s；仍不够时再对助战 2 格做上界剪枝（15% 必带、第二格按「对当前池最大 \(m_c\)」排序）。不引入求解器依赖。

## 8. 对照候选（v1 不实现）

调研全文见 `docs/research/auto-team-algorithm-survey.md`。对齐后的问题**不是**一般二次背包：\(A\) 为输入常量，非线性已消失。

| 角色            | 方法                                     | 何时才需要                               |
| --------------- | ---------------------------------------- | ---------------------------------------- |
| v1 精确（采用） | §6 光环枚举 + 线性背包                   | 当前规模                                 |

## 9. 例子

### 9.1 光环匹配

本队 2 Caster + 1 Saber，场上 1 张 Caster 礼装 + 1 张 5%：Caster 各 \(100+20+5=125\%\)，Saber \(105\%\)。助战再戴一张 Caster 礼装：Caster 各 \(145\%\)，Saber 仍 \(105\%\)。

### 9.2 默认 vs 星级优先

\(K_{\max}=5\)，\(W=80\)，无锁定，无冠位，无助战。池里有若干 ★1 多特性从者和 ★5。

- 默认：会带多张特性礼装（每张 16）和低星多特性从者，收益通常更高。
- 星级优先：先上 5 个 ★5（cost 80），付费礼装全空；再在这 5 个 ★5 里挑特性最能凑到**免费礼装**的组合。若无助战、无冠位，则没有任何免费礼装位，队伍就是 5 个收益 100% 的 ★5（再加锁定带来的 \(A\)）。

### 9.3 同收益刷 cost

星级优先关闭。某格用 ★4 或 ★5 收益同为 100%（都吃不到特性/职阶礼装），剩余 cost ≥ 16：换 ★5。玛修若与某 ★1 收益相同，默认模式会换成正 cost 的人；她通常特性更多，收益更高，不会走到这一步。

### 9.4 虚拟从者

只筛 Rider，有 Rider 礼装：只用 Rider 真从者 + Rider 虚拟从者。只筛 Rider+Archer：Rider 虚拟从者吃 Rider 礼装，Archer 空位用通用虚拟从者指代。
