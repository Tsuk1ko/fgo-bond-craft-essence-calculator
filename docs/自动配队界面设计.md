# 自动配队界面设计

术语以 [`CONTEXT.md`](../CONTEXT.md) 为准。算法输入以 [`自动配队计算算法设计.md`](./自动配队计算算法设计.md) 为准。本文件只约定 **UI 结构与交互**，不涉及求解实现。

示意图：[`mockups/auto-team.html`](./mockups/auto-team.html)（用浏览器打开）。格位解剖：[`mockups/slot-anatomy.svg`](./mockups/slot-anatomy.svg)。

---

## 1. 目标

为已完成的自动配队算法提供独立入口页面，让玩家在熟悉的查看器视觉语言里完成四件事：

1. 填规划条件（队伍位置、星级优先、虚拟从者配额等）
2. 按格位锁定从者 / 礼装，或打开格位特殊设置
3. 发起一次配队计算
4. 在格位上直接读懂结果（谁上场、戴哪张礼装、收益与已用 cost）

成功标准：不读文档的玩家也能分清「锁定」与「自动填入」，能在桌面与窄屏上点完从者 Dialog 和礼装浮层，且主按钮始终找得到。

---

## 2. 设计原则

延续现有查看器，不另起视觉体系。

| 原则 | 落地 |
|------|------|
| 组件库 | Element Plus，沿用 `el-form` / `el-check-tag` / `el-input-number` / `el-button` / `el-dialog` / `el-popover` / `el-switch` |
| 色板 | 默认浅色主题（主色 `#409EFF`、警告 `#E6A23C`、危险 `#F56C6C`、文字 `#303133`），不用新品牌色 |
| 密度 | 与查看器一致：表单项间距 8px，标签 18px 加粗，页面左右 padding 沿用 `--page-x-padding` |
| 图像 | 从者继续用 `ServantImg`（桌面查看器 64px；配队格放大到 80px，因为一屏只有 3～6 格）。礼装没有现成立绘时用色条 + 名称，比例仍按「同宽、高约 1/3」 |
| 图标 | `@element-plus/icons-vue`（查看器已用 `Setting`），禁止 emoji 当图标 |
| 入口 | 配队是独立入口，不复用查看器 `id < 0` 的职阶占位 |

检索到的新设计系统（青绿 + Plus Jakarta Sans）**不采用**，以免和现页割裂。采纳的只有密度偏仪表盘、动效克制这两点。

## 3. 信息架构

```
顶部：查看器 | 自动配队     GitHub
自动配队页
  ├─ 可收起的基础设置（与查看器同一套 form）
  ├─ 常驻操作条：开始配队 + 收益 / cost
  └─ 配队板：3～6 个格位
       ├─ 格位设置浮层
       ├─ 从者选择 Dialog
       └─ 礼装选择浮层
```

查看器与配队用同一套顶栏切换（`el-check-tag` 成组，和「隐藏从者 + 齿轮」同一语言）。当前页高亮。深链：`#viewer` / `#team`，刷新不丢入口。

从者池的隐藏名单与查看器共用；职阶 / 星级筛选在配队页有**自己的**一份，只影响自动上场，不影响锁定。Dialog 内筛选是临时找人用的，关闭即丢，不写回页面筛选。

## 4. 页面布局

查看器是「上表单 + 下从者网格内滚动」。配队页内容更高（配额表、格位），仍套在现有 `html/body overflow: hidden` 里：外层 `container` 纵向 flex，**主列自己滚**，不要整页与内层双滚动条抢手势。

### 4.1 基础设置（可收起）

与 `App.vue` 相同的 `el-form` + 右下「收起 / 展开」。默认展开。收起后操作条仍在，避免主按钮被藏进折叠区。

**第一屏只放高频项**，其余进「更多」：

| 表单项 | 控件 | 说明 |
|--------|------|------|
| 队伍位置 | `el-input-number`，3～6，默认 6 | 用术语「队伍位置」，不用「队伍数量」 |
| cost 上限 | `el-input-number`，56～118 | 算法必填，建议默认 113 |
| 星级优先 | `el-check-tag` | 与「隐藏从者」同一开关形态 |
| 礼装库存 | `el-check-tag` 组，可换行 | 见 §4.2 |
| 从者池 | 复用 `ClassFilter` + `StarFilter` | 可再收进二级折叠；空选 = 不限制 |
| 虚拟从者 | 配额矩阵 | 默认折叠，见 §4.3 |

`cost 上限` 与 `礼装库存` 不在最初功能清单里，但没有它们页面无法驱动现有 `PlannerInput`，所以纳入界面。特性筛选（查看器的「属性 / 组合」）**不出现在页面级从者池**：规划输入没有特性过滤。

### 4.2 礼装库存

每种 0 或 1 张，交互做成查看器属性行那样的 Check Tag：

- 职阶礼装：Caster、Rider、Saber、Assassin（与 `classBonusList` / `classCeClasses` 对齐）
- 特性礼装：`typeList` 全表
- 通用 10%：一枚 Check Tag
- 通用 5%：不提供开关（无限张，文案写在标签旁即可）
- 通用 15%：不提供库存开关（仅助战格可选，规划时自动可用）

标签过多时 **换行**，禁止单行裁切。右侧保留「清除」。

### 4.3 虚拟从者配额

算法按 **职阶 × 星级** 计数，默认每档 6。页面级不铺 15 职阶 × 5 星：职阶虚拟从者只对有职阶礼装的职阶生效。

默认折叠的表格：

|  | ★1 | ★2 | ★3 | ★4 | ★5 |
|--|----|----|----|----|----|
| Caster | 6 | 6 | 6 | 6 | 6 |
| Rider | 6 | 6 | 6 | 6 | 6 |
| Saber | 6 | 6 | 6 | 6 | 6 |
| Assassin | 6 | 6 | 6 | 6 | 6 |
| 通用 | 6 | 6 | 6 | 6 | 6 |

单元格用小号 `el-input-number`（0～6）。表头提供「全部重置为 6」。辅助说明：「其他职阶没有职阶礼装，由通用虚拟从者代表。」

职阶行与 `classBonusList`（Caster / Rider / Saber / Assassin）对齐。

窄屏不要横向裁切整表：改成「先选一行（职阶），再编该行 5 个星级」，或让表格在主列内横向滚而页面本身不横滑。

### 4.4 常驻操作条

设置区和配队板之间，始终可见：

- 主按钮 **开始配队**（`el-button type="primary"`）。计算中：`loading` + `disabled`，防连点。
- 右侧结果：**羁绊收益 650%** · **已用 cost 112 / 118**。未计算时显示「—」。数字用等宽/tabular，避免位数变化把布局撑跳。
- 失败：`el-message` 说清原因（例如锁定礼装超出 cost），按钮恢复可点。

一屏只有这一个主 CTA。

## 5. 配队格

队伍位置变化时，格位数马上变。格从左到右 1…N，与算法 `slots[]` 下标一致。默认第 N 格不是助战；助战由格位设置打开，且全队最多 1 个。打开助战后建议把该格留在最右（与游戏组队习惯一致），但 **不自动换位**，避免用户找不到刚设置的格。

桌面：一行排开，不足则换行。窄屏：每行 3 格（6 格为 3+3），禁止整页横向滚动。

### 5.1 格位结构

从上到下：

1. **格头**：序号、状态标签、设置按钮
2. **从者区**：正方形头像，边长 `--slot-face`（桌面 80px，≤768px 为 64px）
3. **礼装区**：宽度 = `--slot-face`，图片高度 ≈ `--slot-face / 3`。非冠位 1 张；冠位上下 2 张

状态标签用文字，不只靠颜色：`助战` / `冠位` / `羁绊15` / `开16`。标签 `nowrap`，放不下就换到格头第二行，不把字裁成两行碎片。

设置按钮是图标按钮，`aria-label="第 n 格设置"`，点击热区不小于 44px（视觉图标可更小）。已有可见标签时，图标对读屏 `aria-hidden`。

### 5.2 从者区

| 状态 | 画面 | 点击 |
|------|------|------|
| 未锁定、未计算 | `empty.webp` + 「锁定从者」 | 打开从者 Dialog |
| 已锁定 | 从者头像 + 左上锁角标 | 打开 Dialog（可换人） |
| 自动填入 | 从者头像，无锁 | 打开 Dialog（可改成锁定） |
| 职阶 / 通用虚拟从者 | `unknown-servant.webp` + 职阶标（复用 `ServantImg` 虚拟态） | 不可点选进图鉴；点击仍打开 Dialog，便于改成锁定真从者 |
| 助战格 | 中性占位 + 「助战」 | **不打开** Dialog；规划不选助战从者 |

锁定角标不只靠颜色：三角形 + 锁形图标。自动填入无角标，靠「没有锁」和结果数字区分。

未计算时空态必须自带短文案，不能是一块空白。

### 5.3 礼装区

礼装图与从者同宽、高约三分之一，看起来像组队界面里头像下的细条。仓库里暂无礼装立绘时：

- 色条（职阶 / 特性 / 通用用不同填充）+ 深色渐变上的名称与加成
- 名称至少 12px，对比 ≥ 4.5:1；条本身太矮就让 **可点热区含色条下方一行名称**，图片高度仍是 1/3

| 状态 | 画面 | 点击 |
|------|------|------|
| 未锁定、未计算 | 浅底 + 「锁定礼装」 | 打开礼装浮层 |
| 已锁定 | 对应色条 + 锁角标 | 打开浮层 |
| 自动填入 | 对应色条，无锁 | 打开浮层 |
| 空置（规划后仍空） | 更浅的空槽，无「点击」暗示以外的假内容 | 仍可点，改为锁定某张或保持自动 |
| 非冠位 | 只显示 1 条 | — |
| 冠位 | 上条为第一张（免费位），下条为第二张（计 cost） | 各点各的 |

助战格的礼装仍可点：助战只规划礼装。

## 6. 格位设置

点击格头齿轮，在按钮旁打开 `el-popover`（不要用全屏 Dialog，开关只有四个）。Esc 与点遮罩关闭。窄屏可用同一 Popover，内容少，不必换成抽屉。

| 开关 | 默认 | 规则 |
|------|------|------|
| 助战 | 关 | 全队最多 1 个。打开本格则关掉其他格的助战。打开后从者区改为助战占位，羁绊 15 / 开 16 禁用 |
| 冠位 | 关 | 打开后出现第二礼装条。含助战格 |
| 羁绊15 | 关 | **仅已锁定从者**可开。开：该格提供羁绊15光环 |
| 开放16上限 | 关 | 仅当「羁绊15」为开时可开。开：该从者仍可获羁绊 |

禁用项保持可见，降低透明度，并用 `disabled`；旁注例如「锁定从者后可设置」。不要隐藏开关，否则规则不可发现。

关掉「助战」时从者区恢复可点。关掉「冠位」时第二礼装若已锁定：Popover 内确认「将清除第二张锁定礼装」，或关掉冠位的同时静默丢掉第二张并 `el-message` 说明。推荐后者（一次操作，可在 message 里 Undo 更好，但非必须）。

## 7. 从者选择 Dialog

点击非助战从者区 → `el-dialog`。布局刻意做成 **当前查看器的缩小版**：

- 上：职阶、星级、属性、组合（直接复用 `ClassFilter` / `StarFilter` / `TypeFilter` / `TypeCombination`）
- 下：`ServantSelector` 网格

差异（必须写进实现备忘，以免误复用查看器虚拟从者）：

- 单选。点一名真从者即选中、关闭 Dialog、该格锁定
- **不展示** 查看器 `id < 0` 的职阶占位
- 不进入「隐藏从者」多选模式
- 底部次按钮 **清除锁定**：该格从者改回自动
- 标题「选择第 n 格从者」，右上关闭，Esc 关闭
- Dialog 打开时焦点进关闭按钮或筛选区；关闭后焦点回到该格从者区
- 筛选状态是 Dialog 私有的，关掉就丢

已在其他格锁定的从者仍显示，但点了要 `el-message`：「该从者已锁定在第 x 格」，不关闭 Dialog。

---

## 8. 礼装选择浮层

点击礼装条 → 锚在该条上的 `el-popover`，不要再开一层 Dialog。宽度约 240～280px，列表可滚。

选项顺序：

1. **自动**（解除该礼装位锁定）
2. **空置**（锁定为空，规划不得往这里塞礼装）
3. 分组：职阶礼装、特性礼装、通用

本队格只列出 **已勾选库存** 的有限礼装 + 5%。助战格列出完整目录（含 15% 与未拥有的职阶 / 特性礼装）。15% 只出现在助战格。

当前选中项要有 `aria-pressed` / 选中描边，不能只靠颜色。点一项即写入并关闭。Esc 关闭。

冠位两张条互不影响；同一张有限礼装不能在本队两格同时锁定，第二处要点时提示冲突。

## 9. 交互总表

| 用户动作 | 界面反应 |
|----------|----------|
| 改队伍位置 | 格位数变；多出来的格为空；删掉的格其锁定一起丢，必要时 `el-message` |
| 点开始配队 | 按钮 loading；格内自动位更新；操作条写收益与 cost |
| 计算未完成时改条件 | 结果数字标为过期（例如「过期」标签），不偷偷用旧结果冒充新结果 |
| 点锁定从者 | Dialog；选中后该格锁角标出现 |
| 点助战从者区 | 无 Dialog；可 toast「助战格不选择从者」 |
| 点礼装条 | 礼装浮层 |
| 点齿轮 | 格位设置 |
| 打开羁绊15 但未锁定从者 | 开关 disabled |
| 破坏性清除（清锁定、清库存） | 与查看器一样用 `el-popconfirm` 的，才用确认；单格「清除锁定」不必二次确认 |

动效：hover / 开关 150～200ms；Dialog 从触发格淡入。`prefers-reduced-motion` 时切到无位移。不要用宽高动画撑布局。

## 10. 响应式

沿用现有断点：768 / 992。

| | 桌面 | ≤768px |
|--|------|--------|
| 页边距 | `--page-x-padding: 64 / 32` | 24px |
| 表单标签 | 18px | 14px |
| 格位头像 | 80px | 64px |
| 礼装条高 | ≈27px | ≈21px（热区含名称行，保证易点） |
| 配队板 | 一行最多 6 | 一行 3 |
| 从者 Dialog | 约 90vw × 80vh | 几乎全屏，保留关闭 |
| 主按钮 | 操作条左侧 | 操作条全宽，结果换行到按钮下 |

格位点击不依赖 hover。现有 `user-select: none` 保持。

## 11. 无障碍（本页必做）

- 正文与标签对比 ≥ 4.5:1；主色白字按钮按 Element Plus 默认即可
- 焦点环可见，含 Dialog / Popover 内控件；不要 `outline: none` 后不补
- 图标按钮有 accessible name；装饰性职阶图在有文字标签时 `alt=""` 或 `aria-hidden`
- 格位状态不只靠色：锁角标、文字标签、`aria-pressed`
- 计算中按钮 `aria-busy`；结果区 `aria-live="polite"`（不抢焦点）
- Tab 顺序：设置 → 操作条 → 格 1..N（先从者后礼装）→ 齿轮
- 模态：Esc 关闭；焦点不落到遮罩后的格位上

## 12. 与 `PlannerInput` 的对应

| 界面 | 字段 |
|------|------|
| 队伍位置格列表 | `slots.length` 3～6 |
| 格 · 助战 | `slots[i].isSupport`（至多 1） |
| 格 · 冠位 | `slots[i].isCrown` |
| 格 · 锁定从者 | `slots[i].lockedServantId` |
| 格 · 锁定礼装 | `slots[i].lockedCes` |
| 格 · 羁绊15 / 开16 | `slots[i].bond15` / `bondCap16` |
| cost 上限 | `costCap` |
| 星级优先 | `starPriority` |
| 从者池职阶 / 星级 | `selectedClasses` / `selectedStars` |
| 查看器隐藏名单 | `hiddenIds` |
| 礼装库存 | `ownedTraitCes` / `ownedClassCes` / `ownedGeneric10` |
| 配额表 | `quotaClass` / `quotaGeneric` |

页面不提供 `servantIds` 细选名单：默认图鉴全体真从者，再叠加隐藏与职阶 / 星级筛选。锁定 id 即使被筛掉也必须能上场（算法已保证）。

## 13. 建议复用的现有块

- `ClassFilter`、`StarFilter`、`TypeFilter`、`TypeCombination`、`ClearBtn`
- `ServantSelector` + `ServantImg` + `ClassIcon`（Dialog 内；去掉查看器虚拟从者）
- 查看器表单的收起按钮与 `--page-x-padding` 节奏

新画面（只设计，不在本次落地）：`ModeSwitch`、`TeamBoard`、`TeamSlot`、`SlotSettingsPopover`、`CePickerPopover`、`QuotaMatrix`、`CeStrip`。

从者 Dialog 体量大，实现阶段用 `defineAsyncComponent` 懒加载即可；这是性能约束，不是视觉约束。

---

## 14. 明确不做

- 不在结果里列出多组最优解
- 不做拖拽换位（WCAG 拖拽还要另做指针替代；格少，锁定已够）
- 不把查看器属性筛选接到规划从者池
- 不在助战格选从者
- 不引入新色板、新字体、新图标库
- 本次不实现页面代码
