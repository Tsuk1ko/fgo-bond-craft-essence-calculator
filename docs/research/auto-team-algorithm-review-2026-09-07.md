# 自动配队算法复核与优化研究

日期：2026-09-07。历史实现基线：`edb160d`。术语和当前约束以 [`CONTEXT.md`](../../CONTEXT.md)、[需求](../自动配队计算算法需求.md)和[修订设计](../自动配队计算算法设计.md)为准。本文保留对[旧调研](./auto-team-algorithm-survey.md)和历史实现的复核证据，并补充已授权的实施边界；历史测量不代表修订后的实现。

**推荐保留「合法礼装光环枚举 + 精确选人」，把每配置的全池背包换成「同 cost top-K + 分组前缀和 + 人数向量枚举」。** 先修复可行性和回溯问题，再做光环去重、公共分数复用，最后才考虑分支定界。当前规模没有必要先引入通用求解器或放弃最优性。

本文明确区分三类证据：项目代码可直接核查的事实；依据当前规则给出的数学推导；本次本机原型测量。外部来源只支撑其实际讨论的算法或 API，不把其他问题上的论文速度转写成本项目速度。

本轮采用合法光环枚举、同 cost top-K、前缀和及恰好人数向量、星级/cost 分组和玛修分支、助战无序组合、选择性光环评分复用、公共加成常量。完整合法枚举建立后取消每候选重打包，最终恢复见证并复算。Worker/UI、CP-SAT、近似算法和分支定界不在本轮范围；「只做精确、两秒、Worker」是设计 v1 选择，原始需求允许近似。

## 1. 当前问题的有效结构

- 未锁定从者全部可获羁绊，不会发羁绊 15 光环；发光环人数 `A` 由锁定格固定。
- 固定一组**合法、可实际放置**的礼装张数 `C` 后，未锁定从者收益是独立的线性分数 `v_i(C)`。从者 cost 只有 `{0, 3, 4, 7, 12, 16}`；cost 0 只有玛修。
- 一个从者能戴哪些未锁定礼装只由格子类型决定，收益与佩戴者无关。除锁定外，相同类型的空格可互换。
- 需要最多 6 个本队格，真从者不可重复；虚拟从者是有上限的同类份数。
- 本队可选的有限库存礼装最多 12 种：8 特性、3 职阶、10%。加上 5% 与助战专用 15%，完整种类是 14 种，不能把两个口径混用。
- 默认目标是 `(收益, 已用 cost)` 字典序最大。星级优先是 `(n5,n4,n3,n2,n1,n0,收益,已用 cost)` 字典序最大。

完整问题仍有 `礼装张数 × 命中从者人数` 的双线性项。`A` 固定只消除了羁绊 15 的选择耦合；必须再固定礼装配置，选人才完全线性化。

以下记 `P` 为未锁定池中从者种类数，`K` 为待选人数上限，`W` 为剩余 cost，`D` 为 cost 档数（当前 6），`Q` 为助战可选礼装种类数（最多 14），`L` 为合法光环配置数。

## 3. 同 cost top-K：精确地缩小选人池

### 3.1 交换论证

固定光环、锁定从者和待选人数上限 `K` 后，将其余候选按**实际 cost**分组。在每组按收益降序保留前 `K` 份；真从者仅 1 份，虚拟从者贡献 `min(剩余配额,K)` 份。

某个可行解若用了组内第 `K+1` 名或更后面的候选，该组至多选了 `K` 人，因此前 `K` 名至少有一份没被选。用它替换，人数、cost 和合法份数不变，收益不降。重复交换后，总存在一个最优解完全来自这些前 `K` 份。因此默认模式只需保留最多 `D*K <= 36` 份；利用玛修只有一份，实际上最多 `1+5*K <= 31` 份。

这是本文按项目规则给出的证明，不是经验性的「取一些高分人应该够」。同分时只需稳定选一个合法代表；成本相同，第二目标不受损。

**前提不能省略：**

1. 分组在每个光环配置下重新评估。不能按空光环或单张礼装的分数先永久截断候选。
2. 锁定从者已移出选择池、扣除 cost、计入常量收益；虚拟配额按真实可用份数处理。
3. 此时没有待满足的额外职阶人数下限、必须具备某特性之类的组合约束。若以后增加，需相应扩展状态。
4. 星级优先不能把同为 cost 4 的零星与二星混为一个优先级；应按 `(star,cost)` 分组，或先固定星级向量再选人。玛修与普通四星的 cost 不同，必须分别处理。
5. 同特性桶不能只保留一个从者：若最优队伍需要同桶 3 名，保留 1 名会丢解。可合并为保留至多 `K` 个可恢复 ID 的计数桶。

实现可以用最多 6 项的有序小数组，不需要堆或第三方库。为每个物品定位一次插入点，再批量插入最多 `K` 份，扫描代价 `O(P*K)`；若简单地逐份插入，虚拟份数会再带来至多 `K` 的因子，当前虚拟种类最多 20，实测再决定是否优化。

### 3.2 前缀和 + 小分组 DP

对 cost 为 `d` 的组，记收益排序为 `v[d,1] >= ...`，前缀和：

```text
prefix[d,0] = 0
prefix[d,t] = 前 t 份收益之和
```

一旦决定该组选 `t` 人，最优收益恰好就是 `prefix[d,t]`。因此一组只有 `0..K` 个选项，分别占 `t` 人、`d*t` cost。分组 DP 转移为：

```text
next[k+t,w+d*t] = max(next[k+t,w+d*t], dp[k,w] + prefix[d,t])
```

用独立前后两层，或在保存回溯时保留组层号，避免后续更新改写前驱。复杂度 `O(P*K + D*K^2*W)`，分值内存 `O(K*W)`；相对原逐从者 DP，把主要转移中的 `P` 换成 `D*K`。`W<=118` 下足够小，但不是当前最简的最终选项。

### 3.3 更适合当前规模：直接枚举各 cost 的人数

枚举 `(n0,n3,n4,n7,n12,n16)`，限制总人数和预算，计算：

```text
人数 = sum(n[d])
cost = sum(d*n[d])
收益 = sum(prefix[d,n[d]])
```

cost 0 只有玛修，所以 `n0` 只有 0、1。忽略实际池容量和预算剪枝，对 `K=6`：

- 恰好 6 人：不带玛修 `C(10,4)=210`，带玛修 `C(9,4)=126`，总计最多 **336** 个向量。
- 至多 6 人：不带玛修 `C(11,5)=462`，带玛修 `C(10,5)=252`，总计最多 **714** 个向量。
- 若以后不再只有一名 cost 0 从者，通用 6 档的至多 6 人向量上界为 `C(12,6)=924`。

这些是组合数上界，不是跑出来的节点计数。通用表示的枚举量是 `O(C(K+D,D))`，递归汇总前缀值时每条边只做常数工作。`D`、`K` 固定时，池规模只进入前面的线性扫描。最终恢复队伍只需要按最优人数向量取每组前缀，天然不会产生可变 DP 前驱串链问题。

对 `solve` 外层已指定的上场人数，推荐内核**恰好选择剩余人数**，不可行就跳过；外层已枚举更少的人数，内核无需再偷偷减少人数。这样光环容量、可获羁绊人数和实际占位完全一致。

### 3.4 星级优先

先扣除所有锁定从者和**锁定付费礼装**的 cost，枚举满足全部锁定的可行星级向量，再取字典序最大者。只锁礼装的本队格也必须有从者，所以不能仅逐档贪心后遗漏强制占位。求向量时不为可选付费礼装预留预算；之后固定向量，可选礼装不能使它降低。按 `(star,cost)` 取最高收益前缀，四星分别评估「带玛修」与「不带玛修」，先过滤超预算分支，再按收益和 cost 比较。不要先取一个最优名单，超预算时随便替换名单中的第一名四星。

旧设计明写计算星级向量时忽略付费礼装，未区分锁定与可选费用，这是设计漏洞。返回超预算则是实现违反硬约束；两者需分别修复和归类。

同 cost top-K 是默认模式的核心收益；星级模式本来就接近按组取 top，主要改进是局部 top-K、玛修分支正确性、锁定预算与光环结果复用。

## 4. 外层光环枚举比位排列更值得优化

### 4.1 只生成可放置配置

对每个精确上场人数，先确定实际占用格和被锁定礼装占用的格，得到本队剩余免费位、付费位以及助战剩余位。锁定付费礼装的 16 cost 先扣除；锁定库存从其各自来源扣除。

`lockedCes` 按位置允许 `null`，表示该位置尚未锁定，不能把 `[null, ce]` 压缩成第一张锁定。输入冲突、非法来源、有限库存超额或没有满足全部锁定的可行队伍时抛 `Error`。空池且无锁定可以返回空本队；存在助战则仍填满助战礼装。

之后分别枚举本队礼装和助战礼装，要求各自在本来源的剩余容量内。助战不能借本队库存约束，本队也不能借助战免费位降低自身 cost。每个配置保留一个具体可放置见证，或能无歧义恢复见证的计数信息。

历史 `edb160d` 的 `solve.ts` 检查 `premium.length <= total`，然后用全队 `free` 抵扣总张数。无锁定且实际人数恰好为本轮 `K` 时，助战配置始终占满助战位，因此这条聚合公式可以正确反映本队剩余容量及付费张数，不能单独据此判错。但代码没有将锁定礼装作为枚举的固定前缀，内层背包又允许少于 `K` 人，原先假设的锁定约束、冠位容量和实际费用就可能不成立。改为恰好人数是在补齐证明前提，不另计一个已独立复现的 bug。

### 4.2 冠位助战使用无序组合

两张助战礼装都免费，未锁定时交换次序不改变收益和合法性。历史实现枚举有序 `(a,b)`。在当前「有限种类助战内部最多一张，5% 可重复」规则下，`Q=14` 时：

```text
有序组合 = Q*(Q-1)+1 = 183
无序组合 = C(Q,2)+1 = 92
```

差异来自几乎每个不同礼装对都重复处理两次。锁定某一位置时，保留位置锁定语义，仅对余下对称部分去重。不能仅因 15% 是通用高值就强制助战必带：若全队同时命中两种特性，两张 20% 会优于 20%+15%。

### 4.3 精确键和公共分数复用

所有格子合法性已经验证后，若两个配置有相同总光环张数向量、精确上场人数、已付礼装 cost，且锁定/库存残量属于相同输入，那么它们在选人阶段等价，可以只保留一个放置见证。先建立合法性再去重，不能从相同光环反推任意来源分配都可行。

进一步，当前未锁定从者都可获羁绊，通用礼装及固定 `A` 对每个人增加同一个常量。对于固定待选人数：

```text
总收益 = 特性/职阶光环收益 + G*(100 + 25*A + 5*n5 + 10*n10 + 15*n15)
```

`G` 由精确上场人数减去锁定不可获羁绊人数得到。因此通用礼装张数只改变常量和可用预算，不改变同 cost 组的人员收益排序。可以按**特性/职阶张数向量**算一次前缀和，再查询不同预算、人数、通用礼装数。对一个光环向量生成所有可行人数向量，并保存各 `(人数,cost)` 最好值，也可让多个外层预算共用结果。

这不是跨配置永久保留某批从者：只复用在选择性光环相同情况下的排序。

### 4.4 固定队伍打包可以更简单且精确

当前所有可选礼装 cost 一致、光环与佩戴者无关。固定队伍后先算每张礼装的全队价值 `rate * 命中人数`，锁定格先处理。然后分开做：

- 助战：从完整助战礼装目录选择剩余位的最高价值合法组合，不受本队是否拥有影响。
- 本队：用剩余预算确定还能填几个付费位，加上必须填的免费位，选择该数量最高价值的礼装；有限库存各最多一张，5% 是可重复候选。

必须把 5% 和特性/职阶礼装一起比较。6 人队里只命中 1 人的 20% 礼装全队价值为 20，低于 5% 的 30。先取所有正值特性礼装再补 5% 不是精确打包。

在 `G=0` 时，所有已占冠位第一张与助战免费位仍必须填满；付费位按最高已用 cost 目标尽量填。以上论证依赖本队可选礼装没有额外的佩戴者限制、都同为 16 cost；以后有专属装备或不同 cost 才需要更通用的分配算法。

当光环枚举已经完整且合法，每个配置下的最优选人结果直接配上它的放置见证，已足以比较全局最优。不必对每个候选重做一次打包；最终赢家恢复名单和礼装后按业务规则复算收益、cost、份数及锁定。取消重打包是本轮建立上述前提后的等价优化，不是旧规格已要求的行为。

## 5. 精确加速备选：礼装分支定界

优先在礼装选择树上分支，选人仍用上面的精确小内核。相比从者树 `P^K`，有限本队礼装只有最多 12 个「取/不取」决策，更容易界定剩余选择。[S4] 给出合法界限剪枝与 beam 永久截断的区别。

一个便于证明的上界如下。当前选择了部分礼装，剩余最多还能放 `r` 张；对每个候选从者分别取其可获得的最佳 `r` 张剩余加成，甚至放松成每张都按其个人最佳加成计入。暂时忽略这些礼装占用 cost，但仍保留已经强制的礼装 cost；把这些乐观分数送进精确选人内核，并为锁定可获羁绊从者加同样的乐观剩余收益。真实完整配置一定不超过这个界，因为实际礼装需全队共享、还要付 cost。

界可以很松，但必须向上松弛；不可用当前局部队伍实际匹配数充当所有后代的最高匹配数。先用快速完整可行队伍得到 incumbent，按高潜在收益礼装顺序搜索。

只有 `收益上界 < incumbent收益` 才能仅按收益剪枝。相等时仍可能提高已用 cost，应再比较 cost 上界，或保留该分支。星级优先最好先固定最优星级向量，否则上界也必须覆盖完整字典序。

最坏情况仍遍历全部合法配置，且每个内部节点计算上界有开销；没有实测就不能宣称优于直接枚举。若限时终止，保存未展开节点的最大上界 `U` 和当前可行值 `B`，才可报告可证明间隙；仅仅返回当前最好队伍不代表知道间隙。

## 6. 紧凑 CP-SAT / MILP 模型

### 6.1 避免「从者 × 格子 × 礼装」大笛卡尔积

对每个精确上场人数 `K`，沿用冠位优先的合法占位方案，消除格子排列对称性。把锁定从者贡献变成常量，其余每个真从者一个二进制变量 `x_i`，每个虚拟类型一个 `0..quota` 整数变量。约束 `sum(x_i)=待选人数`。星级模式添加各星级人数等式。

设每种选择性礼装 `c`：

```text
m_c = 锁定可获羁绊命中人数 + sum(可命中 c 的候选 x_i)
y_c = 本队装备的该类张数 + 助战装备的该类张数
z_c = y_c * m_c
```

每种有限礼装本队和助战各自不超过一张，当前 `y_c<=2`。本队、助战的张数变量分别遵守容量、库存、锁定要求。本队剩余已填礼装数满足 `剩余免费位 + 新填付费位`，新填付费位有容量上限；助战剩余位必须填满。总 cost 为从者 cost、强制付费礼装 cost 和新付费张数乘 16 之和。

固定 `K` 时 `G` 已知，通用礼装收益是其张数的线性函数；目标为：

```text
Y = G*(100+25*A) + sum(20*z_c) + G*(5*y5+10*y10+15*y15)
```

模型的从者变量约 `O(P)`，光环计数与乘积变量约 `O(礼装种类)`，不是必须 `O(P*K*礼装种类)`。这是基于当前规则的建模推导，未在本次实现该求解器模型，也没有求解速度实测。

### 6.2 CP-SAT 原生乘积与 MILP 精确线性化

OR-Tools 官方文档说明一般线性表达式不能直接乘两个变量，乘积应使用 `add_multiplication_equality`；也提供布尔与整数乘积的条件等式建模。[S1]

纯 MILP 可将 `y_c` 表示为两个有序二进制变量 `q_c1+q_c2`，其中 `q_c2<=q_c1`。分别设 `w_cj=q_cj*m_c`，利用 `0<=m_c<=K`：

```text
0 <= w_cj <= K*q_cj
w_cj <= m_c
w_cj >= m_c - K*(1-q_cj)
z_c = w_c1 + w_c2
```

`q=0` 时这些约束强制 `w=0`，`q=1` 时强制 `w=m`，因此是精确线性化。不要仅对两个一般整数变量加连续 McCormick 松弛后就声称乘积严格等价。这里的二进制拆分使等价性成立。

默认目标可分两次求解：先最大化收益并固定最优收益，再最大化 cost。也可最大化 `119*Y+cost`，因为当前 cost 不超过 118，收益为整数百分点，一单位收益差超过所有 cost 差。星级模式优先固定星级向量，避免引入不必要的大权重。

### 6.3 可证明结果与部署边界

- CP-SAT `FEASIBLE` 表示有解但尚未证明最优，`UNKNOWN` 可能意味着时限内没找到可用解。`best_objective_bound` 对最大化问题是经证明的上界。[S2]
- `OPTIMAL` 也可能在用户设置非零 gap limit 时返回；要宣称严格最优，需检查容差设置与最终界限，而不只看字符串。[S2]
- `max_time_in_seconds` 是求解调用的限制，模型构造、运行时启动、数据序列化和加载另有成本，不能等同于完整交互延迟。[S3]
- SciPy 的 `milp` 使用 HiGHS，提供 `time_limit`、`mip_rel_gap`、`mip_dual_bound` 和状态，可作离线模型验证；浮点求解器结果还应按整数业务规则复算。[S6]
- OR-Tools 官方 README 列出 C++ 与 Python/C#/Java 封装，没有给出可直接采用的浏览器 JavaScript 部署方案。[S7] 不能从「有 CP-SAT」推导成「项目直接加个包即可获得官方 WASM 支持」。若引入第三方 WASM 包，需要另核查维护、体积和加载开销。

当前优先将通用求解器作为独立最优值 oracle；本项目自定义内核已经利用了强约束，未必会被通用求解器压过。

## 7. 允许近似时：VNS 和 beam 应搜索什么

### 7.1 VNS：在礼装配置上做局部搜索

VNS 的核心是改变邻域，在下降和跳出局部最优的阶段系统性切换；提出者在 GERAD 的一手资料明确这样描述。[S5] 对本项目更合适的状态是**合法光环配置**，每次评估用精确选人内核得到队伍，而不是同时随机修改所有从者和佩戴位置。

邻域可依次为：替换一张本队礼装；增删一张付费礼装；更换助战组合；同时替换两张本队礼装。每个邻域动作都必须保持锁定、库存和来源容量合法。星级向量先固定。

一次扫描的配置邻居数约 `O(q^2+Q^2)`，`q<=12`，实际应按可用库存和剩余位生成；`I` 次扫描总耗时为邻居数乘 `I` 再乘一次精确选人内核的代价。可以直接限制评估次数或时间，不需要模拟退火的温度调参。

当前没有「主动插入一个羁绊 15 发光环从者」的合法动作，因为这些状态只允许来自用户锁定。局部最优仍可能存在：两张单独无收益的替换组合后改变最佳队伍。多起点和双替换可降低风险，不提供最优保证；即使有限邻域未再改进，也只能称相对这些邻域的局部最优。

### 7.2 Beam：对礼装决策分层，别展开整个从者池

对最多 12 个有限库存礼装做取/不取的层次选择，再考虑助战和通用填充；每层仅留宽度 `beta` 的候选，用乐观收益或快速可行完成值排序。每层分支数 `b` 较小，主要工作量约为 `O(depth*beta*b*(评估代价+log(beta*b)))`；内存取决于当前候选及是否保存父链，不能脱离实现只报一个毫秒数。

原始 beam 会永久丢弃节点，可能丢失最优解甚至所有可行解。Zhou 与 Hansen 的 ICAPS 原论文明确说明这个局限，并给出带系统回溯的 beam-stack，以增加搜索工作换取最终完备性。[S4] 本项目可以借鉴 anytime 思路，但只需近似时不必实现完整 beam-stack。

宽度 1 是按所用评分执行的贪心路径搜索，不宜不加限定地与所有形式的 hill climbing 画等号。加宽 beam 可以增加保留候选，不能给当前任务预先承诺固定误差界或固定毫秒延迟。

## 8. 旧调研和设计的勘误

本节的「设计」指修订前版本；当前设计已更新。重复真从者和超预算是硬约束实现错误，助战目录受本队库存限制及玛修替换也是实现错误；先取特性再补5%则沿用了不精确的设计补位思路，需要设计与实现一起修订。

### 9.3 后续 benchmark 设计

1. 先用独立穷举验证小池端到端正确性：逐一枚举真从者子集、虚拟份数和合法礼装来源/张数。对照完整目标元组和所有约束，不只比 `totalYield`。
